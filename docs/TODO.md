## 2. P0 — source gap audit (S1–S5 complete; device UAT separate)

- [x] **S1 · Daily steps / Health Connect source reliability (fixed):** audited `FloatingControls.kt` and found a reproducible date-only Health Connect cache defect: a time-zone change without a date change could reuse an aggregate computed from the wrong midnight boundary; reopening the overlay could briefly display old permission-dependent data. Added `FloatingDailyStepsCache` keyed by **local date + IANA time zone**, monotonic 60-second freshness, 15-second bounded retry on unavailable/denied reads, forced revalidation on overlay reopen, cancellation/invalidation on close/rollover, and per-request tokens to reject stale in-flight completions. Pure Kotlin regression tests cover **same-date zone change, midnight, revocation/failure, real zero, stale expiry, concurrent reads, elapsed-clock rollback and 5-second UI tick throttling**. The HC total, local-sensor count and virtual estimate remain separate. **265 JVM tests (0 failures), local Android Lint and [GitHub verify](https://github.com/Naos2w/PikminBee/actions/runs/45153175207) passed; merged via PR #112**; this source fix is not proof of real POCO/HC acceptance.
- [x] **S2 · Route/speed/step source consistency (fixed 2026-11-23):** identified two source defects in `MockLocationService.tick`: (1) reducing an existing looping route to modulo distance **before** detecting speed-leg crossings dropped segment changes when one Android tick crossed several laps; (2) non-loop progress added the **requested** distance instead of the accepted distance, allowing internal progress beyond the terminal route length. Added the pure, testable `RouteTickProgression` used by the service for canonical accepted travel and bounded elapsed time; replaced the duplicate modulo-only speed controller with the existing `WalkSpeedPlayback`, which samples all crossed stops and full laps, reuses current range speed on an identical selection and samples anew for a new route. All virtual step updates still use only accepted route metres; GPS jitter is test-provider-only, and pause/stop/park never generate new travel. Added **11 JVM regression tests** for 0.8/1.4/10.8 presets, custom speed during pause/resume, non-loop terminal clamp, 6 complete laps within one tick, repeated range selection, idle/stop time, jitter-only reports and invalid input. **MSI 276 JVM tests (0 failures/skips), Android Lint exit 0 and [GitHub verify](https://github.com/Naos2w/PikminBee/actions/runs/45155959048) passed; merged via PR #113**. Real POCO App/overlay/Wi-Fi and Health Connect acceptance remains under U1–U3; do not claim device verification.
- [x] **S3 · Virtual step-sync source integrity (fixed 2026-11-23):** audited `EstimatedStepLedger`, `HealthConnectStepSync`, foreground Settings and `EstimatedStepsSyncWorker`. Before this change the manual and background writer could race, disabling consent or discarding a queue during a batch did not stop stale subsequent writes, a 50-item slice could leave 251–500 records stranded after bounded worker retries, a single malformed JSON item could erase the decoded queue, and `todayOwnVirtualSteps()` counted entire cross-midnight records as today's manual estimates. Introduced one in-process sync mutex, a testable consent/pending recheck **per session**, stable `pikminbee-virtual-<session ID>` client-record retries after local ack failure, full ledger drain in bounded 50-item chunks (up to the existing 500-item cap), safe item-by-item legacy decode, and time-proportional **estimated** overlap for cross-midnight own-record counts. User-facing details explicitly identify this day attribution as an estimate, not sensor data. **Still opt-in, with `Metadata.manualEntry`; no new daily cap, Health Connect permissions or third-party sensor spoofing.** Regression tests cover opt-out, discard, permission/write failure, ack retries, coroutine cancellation, 120-/500-item queues and midnight overlap. **MSI 296 JVM tests (0 failures/skips), Android Lint and [GitHub verify](https://github.com/Naos2w/PikminBee/actions/runs/45159520672) passed; merged via PR #114**. Actual POCO permissions, Health Connect accepted records and date rollover remain U3 UAT, not claimed passed.
- [x] **S4 · Route completion / overlay source consistency (fixed 2026-11-23):** audited `MockLocationService`, `FloatingControls`, one-shot `RouteCompletionAlertPolicy` and the shared `LanController` status. Reproduced incorrect source behaviour: opening/closing the overlay overwrote the shared walking, paused or completed status; PARKED overlay always labelled a genuine arrival as manually stopped; resuming FLOWERS falsely displayed ordinary road walking; old completed-route notifications could remain after starting a new route; stopped/cleared/teleported or restored virtual sessions could still expose their previous applied route speed, and a manually stopped route could retain a stale ETA. Added pure `RouteSurfaceStatusPolicy`, kept Android / overlay / paired LAN using the same `LocationStatus` source, preserved actual arrival vs manual-stop labels, cleared old completion notifications only on explicit route lifecycle changes (never just show/hide, pause, OS service reclaim or rejected provider setup), reset visible applied speed/ETA on PARKED or IDLE, and refreshed the overlay on clear. Existing 2×4 controls and existing route loops unchanged. **MSI 308 JVM tests, zero failures/skips; Android Lint exit 0**; new source-policy regression cases cover one-shot completion, overlay visibility, flower resume, restored virtual position, stale alert lifecycle, stopped speed and zero ETA. [GitHub verify](https://github.com/Naos2w/PikminBee/actions/runs/45165050429) passed; merged via PR #115. **POCO sound/vibration, Android notification permission/DND, background service and App/Edge layout remain U2/U7 real-device acceptance—not marked passed.**
