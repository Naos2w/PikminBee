# PikminBee — 花朵畫面辨識原型（待 UAT）

## 需求決策

只研究**使用者明確授權的畫面辨識**，不整合 Overpass／OpenStreetMap 候選花點搜尋，也不接取非公開 Pikmin Bloom API。這個 PR 完全重新實作影像處理，**未複製其他未確認授權專案的原始碼**。

## 已實作

1. 在「尋花」頁籤展開 **畫面花朵辨識（實驗功能）**。
2. 可使用 Android 文件選擇器挑選自己的 PNG/JPEG 等圖片並辨識；圖片只做界限內縮圖解碼，最多約 480×850 像素，分析結束後不寫入檔案。
3. 可按 **授權畫面辨識**，由 Android 顯示 MediaProjection 系統同意對話框，選擇允許分享的畫面範圍；每次重新啟動擷取都要重新取得同意。
4. 獨立 `mediaProjection` 類型的前景服務啟動後，每約 3 秒對最新畫面進行**只讀**辨識；系統通知和 App 均可立即停止。
5. 會將畫面轉為短暫存於記憶體的縮圖像素，以原創 HSV 色彩門檻、連通區域、面積／填充率／長寬比等方式辨識**彩色、部分帶暖色中心的淺色花朵候選形狀**。
6. 顯示候選個數、相對畫面位置及影像特徵分數。**分數不是辨識準確率**。不把候選點當成經緯度，也**不會自動加入尋花路徑**。
7. 偵測接近全黑的畫面時，會顯示空白或內容受保護的提醒。**不繞過 FLAG_SECURE／遊戲防擷取機制**。
8. 畫面原始像素、截圖、MediaProjection 同意權杖、遊戲內帳號都不會持久化、上傳或寫入 LAN API。停止時釋放 VirtualDisplay、ImageReader 及影像權限。

## 與巡花助手的區別

巡花助手的畫面掃描架構可以作為研究靈感，但它的原始碼授權未核實，**本功能從頭編寫**。同時不引入它的 Overpass 地標候選搜尋、定位校正、遊戲畫面偵測規避、觸控自動化或 Health Connect 步數注入。

目前的畫面辨識是**原型**：沒有遊戲真實截圖、沒有人工標記測試集，就不能聲稱對 Pikmin Bloom 大花達到可用準確率。單元測試以程式生成的彩色／淺色圓形、草地、微小雜訊、黑畫面及 UI 干擾進行驗證，只能證明演算法的基本行為。

## 手動像素 → GPS 校正預覽（獨立 Draft PR）

- 使用者在「尋花 → 畫面花朵辨識」選擇自己的**靜態圖片**並完成候選辨識後，可展開「地圖像素 → GPS 手動校正（預覽）」。Android MediaProjection 即時畫面不提供此功能。
- 使用者必須自行提供同一張圖片中 3–16 個分散且已核實的地標：**縮圖後**的像素 X/Y 與 GPS 緯度、經度。PR #11 最初只有手動 X/Y 輸入，需自行換算縮圖座標；後續獨立 Draft PR 加入自選圖片的點選填入，但依然不會自動辨認地標。
- 原創 Kotlin 相似轉換模型只估計局部地圖的平移、等比例縮放、旋轉；**不適用**透視、3D 傾斜、變形地圖，也不能在圖片/縮放/視角變更後重用。對應點過近、共線、超範圍、尺度異常或接近國際換日線會拒絕。
- 顯示 leave-one-out RMSE、最大對應點誤差，以及花朵候選是否位於參考點凸包內。這些只是**使用者輸入地標之間的一致性**，不是獨立量測的花朵 GPS 誤差；凸包外標記為外插。
- 每次新選取圖片都以文件修訂編號重設對應點與估算；不儲存校正點、圖像、GPS 結果，也不啟動/變更瞬移、行走或尋花路徑。只支援本機預覽，不提供可套用的導航座標。
- 本階段完成的是程式碼與合成測試；POCO 的影像操作、真實地標、誤差量測及 UI 實際操作都仍未驗收，**不代表可用於真實遊戲定位**。仍按既定計畫等整合 UAT 才產生測試 APK。

## 靜態圖片點選地標（後續獨立 Draft PR）

- 在手動校正面板中顯示使用者**自行選取**的降採樣地圖圖片，點擊畫面上的已知地標，自動填入縮圖像素 X/Y，再手動確認緯經度；也保留純文字輸入以供替代。
- 圖片採用 `ContentScale.Fit` 中央對齊；純 Kotlin 轉換函式補償上下／左右黑邊、縮放與原圖尺寸。點擊留白區會忽略，不會誤新增校正點。青色標記為待確認位置，黃色標記為已加入的地標。
- 圖片像素僅暫存在目前 Compose 畫面記憶體，不寫入檔案、不放進全域辨識狀態，不傳給 LAN 或其他服務；換圖或授權 MediaProjection 時立刻丟棄舊圖片。若頁面重建，需要重新選擇圖片。
- 每次選取新文件都會遞增文件修訂編號並重設校正點，且忽略比最新選圖更晚才完成的過時分析結果。即時畫面擷取和受保護畫面不會啟用這個選圖面板。
- 本 PR 只增加人工選圖互動與縮放座標換算，**不增加**自動採集、外部候選地點、遊戲觸控、GPS 路線寫入或模擬行走。已完成原始碼編譯及單元測試；真實觸控、排版與定位正確性仍待整合 UAT。

## 下一個技術階段（不能默認已完成）

- **取得明確允許且未受保護的測試截圖**，建立人工標註集，計算 precision／recall，調整白色花朵、各種品種、光影、視角及不同螢幕尺寸。
- **地圖像素 → 世界座標校正** 已有手動輸入、局部相似轉換與內部交叉驗證預覽；下一步仍須以獨立、真實且已核實的地標測試定位誤差。未達可測準確度前，不得自動將花朵像素寫成 GPS 路點。
- 用手機實際測試 MediaProjection 的應用程式分享、全螢幕分享、旋轉後 resize、停止權杖、無畫面／黑畫面和 Android 14+ 新權限。
- 只在整合 UAT 階段產生一次測試 APK，不因單項 TODO 重複打包。
- Pikmin Bloom 及 Android 的內容擷取限制必須尊重；若遊戲封鎖擷取，停止辨識而不是規避保護。

## Android 平台依據

- MediaProjection：每次擷取會話必須取得使用者同意，每個權杖只能建立一次 VirtualDisplay，啟動前景服務後才能取得 MediaProjection：
  https://developer.android.com/media/grow/media-projection
- Android 前景服務類型 `mediaProjection`：
  https://developer.android.com/develop/background-work/services/fgs/service-types

**目前狀態（2026-11-23）：POCO Android 16 / HyperOS 3.0 已以唯讀 ADB 確認 UAT 0.19.1 的使用者授權、MediaProjection 前景服務和 1280×2772 虛擬顯示器啟動，但 PikminBee 對遊戲和普通 Android「設定」畫面都回報「畫面幾乎全黑」。這不等於取得了有效影像，亦不能證明遊戲施加擷取保護；未擷取或保存任何真實畫面。**

**來源層診斷：** 原本將超過 93% 像素 RGB 均小於 30 判定為近乎全黑，會錯誤排除有少量白色文字的深色 UI。後續 F3 原始碼修補採較保守的暗畫面判斷，補充 Android `onCapturedContentVisibilityChanged`、匿名影格數統計與初次 resize 回呼處理。以上**仍需安裝經核准的整合 UAT 後**，以未受保護的 Settings 畫面確認「影格數確實增加、分享區域可見、空白判斷正確」，再測試停止與旋轉。程式測試／CI 不能代替實機驗收，Issue #17 保持開啟。
